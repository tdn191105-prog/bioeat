# Фотографии блюд

`fetch_dish_images.py` один раз скачивает снимки в `static/img/dishes/` и коммитит их
в репозиторий. В рантайме приложение в сеть не ходит: даже без интернета меню
выглядит так же, как на защите.

## Быстрый старт

```bash
# всё, чего ещё нет в static/img/dishes/
DATABASE_URL="sqlite+aiosqlite:///./bioeat.db" python scripts/fetch_dish_images.py
```

Скрипт идемпотентный: уже скачанное он не трогает. В конце печатает сводку и
собирает контактный лист `scripts/out/preview.html`.

**Обязательно откройте контактный лист и просмотрите его глазами.** Автоматический
поиск стабильно приносит 10–20% мусора: под «Солянкой» вполне может оказаться пицца.

## Типовые задачи

| Задача | Команда |
|---|---|
| Перекачать одно блюдо | `python scripts/fetch_dish_images.py --only "Борщ" --force` |
| Перекачать всё заново | `python scripts/fetch_dish_images.py --force` |
| Взять только с Wikimedia | `python scripts/fetch_dish_images.py --provider wikimedia --force` |
| Добавить Pexels | `export PEXELS_API_KEY=...` перед запуском |

`--only` ищет по подстроке названия без учёта регистра, так что `--only "цезар"` тоже сработает.

## Подсунуть своё фото

Папка `scripts/photos_in/` имеет **наивысший приоритет**: если файл лежит там,
провайдеры вообще не опрашиваются.

1. Назовите файл слагом блюда: `borsch-s-govyadinoy.jpg`
   (слаг — транслитерация названия, его видно в контактном листе под каждой карточкой).
2. Подойдут `.jpg`, `.jpeg`, `.png`, `.webp`. Кроп, ресайз и WebP скрипт сделает сам.
3. Запустите `python scripts/fetch_dish_images.py --only "Борщ" --force`.

Содержимое `photos_in/` в git не попадает — это рабочая папка команды.

Разово загрузить фото можно и без скрипта: в админ-панели, в форме редактирования
блюда, есть кнопка загрузки. Такие файлы кладутся в `static/uploads/dishes/`
(подключена томом, переживает пересборку контейнера).

## Заменить поисковый запрос

Запросы лежат в `scripts/image_queries.py` — словарь «название блюда → список запросов»,
которые пробуются по очереди до первого результата.

```python
"Солянка мясная": [
    "solyanka meat soup",                      # сначала самый точный
    "solianka russian soup olives lemon",
    "солянка мясная",                          # русский — последним, выдача беднее
],
```

Английский вариант обязателен: и Openverse, и Wikimedia Commons размечены
преимущественно по-английски. После правки — `--only "Солянка" --force`.

## Как это устроено

Провайдеры пробуются по порядку, до первого результата:

1. **local** — `scripts/photos_in/`, сеть не трогается;
2. **openverse** — `api.openverse.org`, без ключа, только свободные лицензии;
3. **wikimedia** — Commons API, хорошо покрывает русскую кухню (борщ, щи, солянка,
   плов, винегрет, оливье, сырники, ватрушка);
4. **pexels** — только если задан `PEXELS_API_KEY`.

Каждый снимок кропается по центру до 4:3, сохраняется в WebP качества 82 двумя
размерами (`<слаг>.webp` 800×600 и `<слаг>-thumb.webp` 400×300), а по уменьшенной
копии считается доминирующий цвет — им заливается место под фото, пока оно грузится.
Обработка живёт в `app/images.py` и одна и та же для скрипта и для админ-панели.

Автор, лицензия и ссылка на первоисточник пишутся в
`static/img/dishes/attribution.json` и проставляются в базу — приложение показывает
их мелким шрифтом внизу карточки блюда.

Недоступная сеть или пустая выдача скрипт не роняют: блюдо пропускается, причина
попадает в сводку и в контактный лист, обработка продолжается.
